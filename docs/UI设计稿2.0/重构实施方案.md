# 《能量管道乐园》UI 2.0 重构方案

日期：2026-11-09。状态：实施提案，等待制作人确认新增系统范围。

## 目标与设计依据

以本目录 `1.png`、`2.png`、`3.png` 为最新视觉依据，分别还原乐园首页、管道玩法页和设施复苏结算页。尽可能还原构图、角色、场景、材质、边框、图标、字体层级和按钮比例。沿用 React、TypeScript、Vite 与 Capacitor 工程。

保留 99 关拓扑、步数配置、旋转、水闸通断、单向管、十字立交、多源、多目标、撤销、重置、最佳步数、成就和既有存档。界面用乐园、能量、设施等新主题文案表达真实规则。图稿中的关卡、步数、目标和进度示例改为真实数据。

## 两种范围选择

### A：完整还原并补齐本地闭环（推荐，待确认）

首页、玩法、结算与辅助页面全面重构；补齐本地货币、任务、背包与游戏内兑换商店，使设计稿中的入口可用。统一存档和结算，首次通关发放金币与钻石；星星采用真实评级结果；重玩改善星级仅补差额。提示、奖励和兑换的具体数值在范围确认后冻结，禁止将设计示例当作玩家余额。

完成三张主稿和所有既有可达页面；首页只展示已有真实数据，新系统入口暂缓。此方案对首页原稿存在明确可见偏差，须在交付报告中逐项列出。

## 实现组织

1. 确认本提案范围并冻结规格，完成页面测量和完整资产清单。
2. 生成、检查和整理正式美术资产，制作统一字体、颜色、面板和按钮样式。
3. 重构页面外壳、导航和首页，继续使用现有玩法状态与仿真模块。
4. 重构棋盘和特殊管件，接通真实输入、步数、目标、历史和失败恢复。
5. 重构结算和全部辅助页面；按确认范围完成本地系统，统一状态提交和存档。
6. 代码审查、自动化验证、玩家路径试玩、截图对照和返修。
7. 构建可试玩产物，提交本轮代码、正式资产、必要截图与验收报告。

不创建临时工作树；提交仅包含本任务的明确文件。提交前检查并发变更和暂存区，不改写他人历史。

## 验收标准

- 首页、玩法、结算分别与对应原稿并排检查，比较主区块位置、比例、颜色、角色、设施、材质和字形；记录可见偏差，不以自动相似度代替人工看图。
- 在参考比例、9:16 和 9:20 下截图；页面没有文字截断、重叠、超屏、低对比、小到无法阅读的说明或错误裁切。
- 从真实首页进入第一关，旋转通能、撤销、重置、查看提示、胜利、下一关、返回首页和重新启动；通过真实输入证明数据变化与存档恢复。
- 专项试玩水闸、单向管、十字立交、多源和多目标代表关；核对真实规则与新视觉一致。
- 保留旧存档验证升级后的通关与最佳记录；在隔离测试环境验证新玩家路径。
- 若选择方案 A，覆盖首次结算、重复通关、星级提升、任务领取、背包使用、商店兑换、余额不足和重启恢复，保证奖励与扣费来自真实动作。
- 新增模块按需求覆盖自动化测试；运行类型检查、现有玩法回归与正式构建。本次属于全面重构，增加主流程交互覆盖。
- 真机验收先读取并查看当前截图，绑定实际在线设备；每次页面切换重新定位，输入后截图核对，保护用户存档。
- 报告记录测试命令与结果、真实截图、资产检查、试玩路径、已完成项和未覆盖项。尚未取得的真机或视觉证据明确标注，不宣称通过。
