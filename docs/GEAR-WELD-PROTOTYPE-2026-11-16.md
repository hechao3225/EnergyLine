# 齿轮 + 焊死组合实验关（K1–K3，2026-11-16）

> 首页「实验场 · 试玩机制」→ 紫色 **齿焊 K1/K2/K3**。不进主线、不写存档。

## 机制

同时开两条规则：

- `axis`（齿轮）：点组内任意一格，整组按各自方向转 90°（一顺一反）。
- `weld`（焊死）：已经通电的格子不能再转；**组里只要有一格通电，整组一起锁**。

合起来的味道：一次点击同时决定两格的朝向，而且没有回头路——顺序本身就是策略。

## par 为什么仍然精确

和纯焊死一样，用同一个论证：

> 焊死只减少可行的操作顺序，不减少可行解。无焊死的最优计划（组相位 + 单格点击数）
> 如果存在一个合法执行顺序，那么焊死下的最少步数就等于原 par。

生成器先算精确 par，再用 `weldStepsOrder` 的 DFS（现在支持“整组点一下”这种动作）证明最优计划能执行完。
两件都成立才收关；`npm run lab:par` 会一起复核。

## 实现

| 位置 | 改动 |
|---|---|
| `scripts/weld-order.ts` | 泛化成「点击步骤」：`{ axis, taps }` 或 `{ id, taps }`；DFS 时组内任一通电即跳过该组 |
| `scripts/axis-gen.ts` | `GenSpec.weld`：生成时写入 `rules.weld`，不打乱 par 逻辑 |
| `GameBoard` | 焊死锁按**组**判定：组内任一格通电 → 整组所有成员都显示「焊」并禁用 |
| `App` | 点击拦截同样按整组判断（之前就有） |
| `CandyThemeShell` | 首页紫色「齿焊」条目；盘下说明用焊死那句 |
