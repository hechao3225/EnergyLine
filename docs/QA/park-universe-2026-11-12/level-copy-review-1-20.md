范围：`src/content/levels.ts` 1–20、`src/content/collection.ts` 1–20、`src/content/world.ts`、`src/content/zones.ts`，以及 `CandyThemeShell.tsx` 的实际渲染面。

## 0. 一句话结论

1–20 的**核心问题不是“句子不好看”，而是生成器按 id 取模选动作**：长椅会“苏醒”、石阶会“长明”、检票闸会“落成”、音乐盒会“归位”。同时 20 条 `winText` 是同一句式且当前 UI 根本没读；提示里 14 条把“固定管道”写成规则弹窗里不存在的“锁管”。建议先修这三项，再谈润色。

## 1. P0：先修可见的语义/术语问题

### 1.1 标题动作是 id 取模，不是设施语义

证据：`scripts/generate_theme_content.ts`

- `STATE_RULES` / `stateFor`：动作由 `id % states.length` 选出，而不是按设施决定。
- `FALLBACK_STATES` 让 id 6/12/18 都落到“苏醒”，id 7/11/19 都落到“长明”。
- 结果：长椅·苏醒、旗杆·苏醒、雨棚·苏醒、花坛·长明、报时钟楼·长明、石阶·长明、检票闸·落成、音乐盒·归位、邮筒·归位——都不贴设施本身。

标题在首页设施卡、关卡头部可见（`CandyThemeShell.tsx:316/380`）；不是内部字段，玩家能看到。

### 1.2 提示术语和规则弹窗不一致

规则弹窗用的是：`旋转管道 / 能量闸 / 单向阀 / 十字管 / 固定管道`（`CandyThemeShell.tsx:752–776`）。

提示里 1–20 有 **14 条**写“锁管不能转”。“锁管”在规则里没有定义，玩家不知道它指什么。建议统一为“固定管道不能转”。

同类问题：
- “闸要扳通” → 建议“能量闸要扳通”（21+ 的提示里出现）
- “多源分片接” → 建议“多个能量源分开接”（21+）
- “断头管” → 可保留（口语上能懂），或在规则里补一句

### 1.3 `winText` 是死数据，且 20/20 同句式

- `LevelContent.winText` 在 UI 代码中没有读取点；胜利页只读 `collection.name`，清单是静态三段。
- `App.tsx:271` 的 `winText` 属于无尽模式的 `LevelConfig`，不是这 99 条 `LEVEL_CONTENT`。
- 1–20 的 20 条都是 `${facility}恢复运转，失落乐园的星光更亮了。`，99 条同理。

建议二选一：
- **A（推荐，先做）**：从 `LevelContent` 类型、生成器、99 条数据里移除 `winText`，避免以后误以为它在生效。
- **B**：接入胜利页作为一句小字（例如标题下方），再把 99 条重写成每关一句。B 需要 UI 槽位，放到文案定稿阶段再做。

`subtitle`（`失落乐园 · 迎宾门`）同样没有读取点；建议一并移除或明确未来用途。

## 2. P1：模板感与图鉴文案

### 2.1 提示后半句来自 10 条模板池

`ROUTES` 只有 10 条，按 id 循环。1–20 里成对重复：

| 共享同一句的关卡 |
|---|
| 1 / 11：“从最近的一段管道推向…” |
| 2 / 12：“先亮，再回头理岔路” |
| 3 / 13：“先通主路，别绕远” |
| 4 / 14：“留一步余量…” |
| 5 / 15：“清掉断头管” |
| 6 / 16：“往外理，先主后次” |
| 7 / 17：“是关键，先接主干” |
| 8 / 18：“别急着转远端” |
| 9 / 19：“接好后再分能量” |
| 10 / 20：“再补旁边的支路” |

机制前缀（十字管/固定管道/多源）是从真实盘面 tile 统计生成，**准确**，不用动；问题只在后半句。建议 1–20 手写 20 条短路线句，或至少把成对重复拆开。

### 2.2 图鉴 lore / alias 也是模板

- 1–20 的 lore 全部以“位于失落乐园的…”开头，尾巴来自 10 条 `LORE_TAILS` 循环。
- alias 来自 20 条 `ALIASES` 循环，个别不贴设施（例如花坛的“入口第一灯”）。
- 图鉴详情在已修复后会显示 alias + lore（`CandyThemeShell.tsx:877/880`），所以玩家能看到。
- 建议在关卡标题定稿后，单独做一轮 1–20 图鉴改写；不混在这次标题修改里。
