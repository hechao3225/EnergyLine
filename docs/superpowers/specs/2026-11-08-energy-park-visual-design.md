# 能量管道乐园三屏 1:1 视觉还原规格

## 目标

以 `docs/UI设计稿/能量管道乐园三屏界面.png` 为唯一三屏视觉基准，将主页、6×6 解谜页、设施复苏页还原为统一的 900×2000、9:20 竖屏设计坐标。运行时继续使用真实关卡、真实进度、真实步数和真实奖励数据，设计稿中的 40/99、41 关、12 步只作为布局示例。

## 视觉基准

- 设计稿：`docs/UI设计稿/能量管道乐园三屏界面.png`
- 设计坐标：900×2000，所有屏幕元素按比例缩放
- 颜色语言：深蓝紫星空、暖金边框、奶油粉面板、青蓝能量、橙金主按钮
- 字体：中文系统无衬线字体，标题使用高对比粗体，正文保持设计稿的清晰层级
- 适配规则：桌面浏览器和移动端均保持 9:20 内容比例；不拉伸、不裁切主体、不改变三屏主要层级

## 主页

页面层级固定为：HUD → 标题 Logo 与章节横幅 → 乐园主体场景 → 三角色 → 恢复进度卡 → 继续挑战按钮 → 底部导航。

- HUD 保留头像、生命、金币、水晶和设置入口，资源数字动态读取。
- Logo、章节横幅、乐园场景和角色使用正式完整素材；角色锚点与设计稿一致。
- 恢复进度卡显示真实 clearedCount / 99，进度条根据真实数据计算。
- 当前目标设施和章节范围动态计算，不写死设计稿示例数字。
- 底部导航保留五个可操作入口，激活态、图标和文字按设计稿排列。

## 解谜页

页面层级固定为：返回/帮助 → 关卡云牌与星级 → 说明卡 → 6×6 棋盘 → 步数/最佳/星级 → 撤销/重置/提示 → 底部角色装饰。

- 棋盘使用 900×900 棋盘底图和 256×256 透明棋盘元件，端口以公共中心点对齐。
- 保留当前旋转、长按透视、撤销、重置、提示、步数上限和通关判定逻辑。
- 关卡编号、星级、步数、最佳记录和提示次数全部动态读取。
- 交互管道只使用完整 idle/powered 资产，禁止用代码几何块替代正式管道。

## 设施复苏页

页面层级固定为：复苏横幅 → 已修复设施 → 三角色 → 成功说明卡 → 奖励卡 → 返回乐园/下一关按钮。

- 复苏横幅、旋转木马 broken/active 对比、角色和奖励图标使用完整资源。
- 成功说明、奖励数字、步数和下一关状态动态读取。
- 成就 Toast 不得覆盖复苏横幅或成功标题，改为避让布局或延迟出现。

## 素材门禁

正式 UI 只接入具有完整主体、完整透明边缘和正确长宽比的素材。

- 不使用 `fx_energy_arc.png`、`fx_energy_ring.png`、`fx_firework_pink.png`、`fx_firework_blue.png` 这类片段型特效作为独立图标或按钮。
- 资产包中标注为“仅演示状态”或“需再精修”的小尺寸设施不进入三屏正式主体。
- 设计稿中缺失的完整底部导航图标和庆典装饰，使用透明背景生图素材补齐；生成后必须在深色和浅色背景上检查 alpha 边缘。
- 任何主体被裁切、文字缺字、边框断裂、透明边缘异常或不等比拉伸的素材都不能接入运行路径。

## 数据和交互约束

- 所有数据沿用现有游戏状态和关卡逻辑。
- 视觉重构不改变 99 关、星级、步数限制、撤销、提示、成就和设施恢复语义。
- 首页、解谜页、复苏页之间的导航和返回路径保持可达。

## 验收标准

1. 在 9:20 浏览器视口下，三屏主要区块与设计稿的相对位置、尺寸和层级一致。
2. 关键文字完整可读，无截断、溢出、重叠或低对比度。
3. 角色、设施、管道、按钮、面板和资源图标均来自完整正式素材。
4. 第一关可真实完成旋转、通关、复苏、返回首页和选关路径。
5. 运行截图、动态帧和录屏均通过视觉检查；报告记录设计稿对照结果、素材路径、运行命令和剩余风险。
