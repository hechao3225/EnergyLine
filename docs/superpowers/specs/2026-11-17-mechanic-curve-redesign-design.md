## 1. 设计公理（修订）

1. **乐趣来自打破已建立的预期。** 玩家认为环面最好玩、也最难；吸引力来自边界反转、远近重排、跨缝通电和顿悟，而「难」来自空间重构，不是操作精度。所以既给它 **L16–L18 预览**，也在 L26、L51 各留一次回响。
2. **腻来自「每关问同一个问题」。** 同一机制换问题，体感就不同。
3. **新机制很贵。** 能不新增就不新增；日常新鲜感靠提问、组合、换皮。
4. **难度 ≠ par。** par 只算「操作负担」，还要算规则、不可逆、读图三类负担（见第 6 节）。

## 6. 难度模型与审计

### 6.1 四类负担

| 负担 | 由什么决定 | 取值 |
|---|---|---|
| 操作 op | par、源数量、机关数量、目标数量 | 1–5 |
| 规则 rule | 环面 / 焊死 / 齿轮 / 双色 / 禁环 的出现数量 | 1–5 |
| 不可逆 irr | 焊死、零余量取舍 | 1–5 |
| 读图 scan | 诱饵、跨缝、颜色、7×7 | 1–5 |

计算口径（工具实现，文档只定规则）：

- op = min(5, 1 + par / (6 × 格数/36) + 0.5×(源−1) + 0.3×(闸+阀) + 0.5×(目标−1))
- rule = min(5, 1 + 1.0×规则标签数 + 0.5×(齿轮组数 + 颜色区数))
- irr = min(5, 1 + (焊死 ? 3 : 0) + (零容差取舍 ? 2 : 0))
- scan = min(5, 1 + 0.5×诱饵数 + 0.4×穿缝边数 + 0.5×颜色区数 + (7×7 ? 1 : 0))
- challenge = 100 × (0.35×op/5 + 0.30×rule/5 + 0.20×irr/5 + 0.15×scan/5)，取值 20–100

说明：零容差取舍 = goal 关且 maxSteps = parSteps；穿缝边数取自最优解；「是否存在」与「强度」分开计。

### 6.2 两条审计线

- 节奏线（par）：R1、R2、R3、R5。
- 认知线（challenge）：R4、R6、R7。

## 7. 问题轮换与角色

### 7.1 七类问题

| 类型 | 一句话 | 主要机制 |
|---|---|---|
| 定位 | 路在哪、哪条更近 | 基础 / 环面 |
| 顺序 | 先做什么 | 焊死 |
| 取舍 | 放弃谁 | 取舍 |
| 相变 | 怎么一起转 | 联动轴 / 齿轮 |
| 禁忌 | 哪条不能接 | 禁环 |
| 分区 | 谁喂谁 | 双色 / 多源 |
| 规模 | 变大之后怎么办 | 7×7 |

### 7.2 角色

教（首次出现）、练（同块内加深）、变（换叠加）、回声（跨章回归）、谷（纯基础泄压）、考（章内峰值）、boss（章末）。

下降权限：只有「回声」允许 challenge 比同机制上次低；「变 / 考 / boss」不得下降；「教 / 练」在块内不设限。

### 7.3 规则

1. 相邻两关问题标签不得相同。
2. 任意连续 5 关至少 3 个不同标签。
3. 同一主机制连续 ≤6 关。
4. 回声关每章 ≤3，同一机制连续回声 ≤2。
5. 不可逆（焊死）、零容差（取舍）、新空间规则（环面）**不得三样同时出现在一关**；最多两样。
6. 第 4/5 章每关最多 2 种机制，L99 除外。
