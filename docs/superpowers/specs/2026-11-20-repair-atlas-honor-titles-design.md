# 乐园修复图鉴与荣誉称号设计

日期：2026-11-20
状态：待用户审查
范围：H5 主线 99 关的关卡/图鉴合并、成就展示升级、荣誉称号系统
依据：现有 99 关与 99 件藏品的一一对应数据、现有 14 个成就判定、当前关卡选择页与修复手册

## 1. 目标

把“乐园关卡”和“乐园图鉴”合并成一个可游玩、可收集、可阅读的“乐园修复图鉴”。玩家在同一个章节界面里看到所有设施，未修复时是灰色剪影，修复后变成完整藏品。

在现有成就系统上增加荣誉称号。成就负责记录目标和进度，称号负责身份展示。完成关卡、章节和技巧目标后解锁称号，玩家可以在“修复师档案”里佩戴一个称号。

## 2. 核心决策

| 决策 | 取值 |
|---|---|
| 主入口 | 底部导航继续使用“关卡”，进入后标题改为“乐园修复图鉴” |
| 关卡与藏品关系 | 继续使用 `levelId` 一一对应，不新增独立藏品关卡 |
| 图鉴浏览 | 使用现有 5 个章节作为分页，不再保留独立图鉴分页 |
| 卡片内容 | 藏品图、关卡号、设施名、星级、当前/已修复状态 |
| 详情入口 | 点击卡片打开同一页面内的详情面板 |
| 独立图鉴入口 | 删除首页侧边的“乐园图鉴”按钮和独立图鉴弹窗 |
| 局内图鉴按钮 | 打开合并页，并直接定位到当前关卡对应的展品详情 |
| 成就入口 | 保留在头像打开的“修复师档案”，不新增底部导航 |
| 称号来源 | 每个称号由唯一成就解锁，成就保存解锁时间 |
| 称号数量 | 首版 12 个 |
| 称号效果 | 纯展示，不加星级、步数、掉落或战斗数值 |
| 称号佩戴 | 同时佩戴 1 个，可在称号墙自由切换 |

## 3. 数据基础

现有数据已经满足合并条件：

- `LEVEL_CONTENT` 覆盖 1–99 关。
- `COLLECTION` 覆盖 1–99 件藏品。
- 两份数据都使用 `levelId`，形成稳定的一一对应。
- 5 个中心章节分别为 1–20、21–40、41–60、61–80、81–99。
- 现有成就判定已经记录通关关卡、三星关卡、连续三星、四星、无尽连胜和机关使用情况。

本次直接复用 `getLevelContent(levelId)`、`getCollectionEntry(levelId)`、`CENTER_DISTRICTS` 和现有星级计算。关卡难度、盘面、通关条件、首通奖励和章节解锁条件保持不变。

## 4. 乐园修复图鉴

### 4.1 页面结构

页面标题：`乐园修复图鉴`

从上到下依次为：

1. 五个章节页签，保留章节锁定标记。
2. 当前章节进度条：已修复数量、章节总数量、本章星星数。
3. 20 个设施卡片，使用 4 列网格。
4. 当前章节全部修复后的章节荣誉条。
5. 无尽挑战、关卡工坊和世界地图入口。

独立图鉴中的分页按钮、收集说明和返回按钮全部移除。章节本身就是图鉴分页。

### 4.2 卡片状态

每张卡片展示：

- 左上角关卡号。
- 设施藏品图。
- 设施名称。
- 当前获得的星级。
- 地狱关标记。
- 已修复、未修复、当前关卡三种状态。

| 状态 | 视觉 |
|---|---|
| 未修复 | 灰色剪影、低对比度底板、名称保持可见 |
| 已修复 | 完整彩色藏品图、暖色底板、显示星级 |
| 当前关卡 | 金色描边与呼吸光，同时叠加已修复或未修复状态 |
| 章节锁定 | 不显示可点击卡片，保留现有章节锁定说明 |
| 章节全修复 | 章节标题旁显示金色章节徽记 |

卡片名称完整显示，统一使用现有短名称。字号和两行上限需要在 360px 宽度下验证，不允许截字、溢出或压缩到不可读。

### 4.3 设施详情

点击卡片后在当前弹窗内切换到设施详情，不叠加第二层弹窗。

详情包含：

- 大尺寸藏品图，未修复时为剪影。
- 设施名称和别名。
- `第 N 关 · 章节名`。
- 已修复时显示完整藏品故事与祝福文案。
- 未修复时显示收录提示，不提前展示完整故事。
- 最佳步数、最高星级和本关机制标签。
- 主按钮“开始修复”或“再次挑战”。
- “返回本章图鉴”文本按钮。

从局内顶部的图鉴入口进入时，直接打开当前关卡的设施详情。主按钮返回当前关卡，不重新选关。

### 4.4 移除独立图鉴

实施后删除以下入口：

- 首页侧边操作中的“乐园图鉴”。
- 关卡页底部的“查看乐园图鉴”。
- `flora` 独立弹窗及独立分页状态。

`CandyThemeShell` 中现有 `exhibitId` 仍用于控制设施详情，但它归属于合并后的关卡弹窗。`collectionPage` 状态删除，章节状态成为唯一分页口径。

## 5. 称号系统

### 5.1 分层

| 层 | 作用 | 展示位置 |
|---|---|---|
| 设施藏品 | 记录每关修复结果和故事 | 乐园修复图鉴 |
| 成就 | 记录长期目标、条件和进度 | 修复师档案 |
| 称号 | 展示玩家身份和阶段成果 | 修复师档案、首页档案、通关结算 |

称号由成就解锁。没有对应成就解锁时，称号保持锁定。同一成就重复检查不会重复发放称号。

### 5.2 首版称号

| 成就条件 | 称号 | 分类 |
|---|---|---|
| 完成第 1 关 | 初亮星火 | 成长 |
| 完成第 10 关 | 巡园修复师 | 成长 |
| 累计完成 30 个关卡 | 星光工程师 | 成长 |
| 累计完成 50 个关卡 | 乐园守护者 | 成长 |
| 完成失落乐园 1–20 关 | 引灯人 | 章节 |
| 完成星光花园 21–40 关 | 花期守望者 | 章节 |
| 完成云端奇境 41–60 关 | 云桥引路人 | 章节 |
| 完成虹彩天桥 61–80 关 | 虹光调校师 | 章节 |
| 完成梦幻之巅 81–99 关 | 乐园复兴师 | 章节 |
| 任一关卡获得四星 | 零误差校准师 | 技艺 |
| 5 个不同关卡获得三星及以上 | 稳态校准师 | 技艺 |
| 20 个不同关卡获得三星及以上 | 完美回路师 | 技艺 |

首版只为已有成就建立称号映射，并新增不足的成就。现有成就 ID 和解锁时间保留。

### 5.3 成就补充

保留现有 14 个成就，新增以下目标：

- 累计完成 30 个关卡。
- 累计完成 50 个关卡。
- 完成星光花园 21–40 关。
- 完成云端奇境 41–60 关。
- 完成虹彩天桥 61–80 关。
- 完成梦幻之巅 81–99 关。
- 20 个不同关卡获得三星及以上。

现有成就直接映射称号：

| 现有成就 ID | 称号 |
|---|---|
| `first_spark` | 初亮星火 |
| `master_engineer` | 巡园修复师 |
| `circuit_grandmaster` | 引灯人 |
| `speed_optimizer` | 零误差校准师 |
| `perfectionist` | 稳态校准师 |

`circuit_grandmaster` 当前条件为累计完成 20 关，与第一章全部完成同步达成，因此作为“引灯人”的来源。其余新增成就使用新的稳定 ID，不复用旧 ID 表达不同条件。

### 5.4 称号墙

“修复师档案”顶部显示：

- 小羊头像。
- 已修复设施数、总星数和成就数。
- 当前佩戴称号。

档案提供两个页签：

| 页签 | 内容 |
|---|---|
| 称号墙 | 12 个称号、解锁状态、来源条件、佩戴按钮 |
| 成就 | 按成长、技艺、进度、无尽分组，显示实时进度 |

称号卡使用现有奖励缎带与图标体系，按分类使用不同底色：

- 成长：金色。
- 章节：章节主色。
- 技艺：青绿色。

已解锁称号完整显示；未解锁称号显示名称、条件和进度。玩家点击已解锁称号即可佩戴，不需要二次确认。

### 5.5 首次解锁与默认佩戴

如果玩家当前没有佩戴称号，首次解锁称号时自动佩戴，确保奖励立即可见。之后解锁新称号只提示，不自动替换玩家当前选择。

旧存档没有称号字段时默认为空。读到不存在的称号 ID 时回退为空，不阻塞档案页。

## 6. 通关结算

通关结算增加两块信息：

1. 图鉴收录：`图鉴收录 +1 · {设施名}`，明确本关对应藏品。
2. 称号提示：本次新解锁称号时显示一条称号缎带。

如果本次同时解锁多个称号，在结算面板内纵向排列，不连续弹窗。已有称号不会再次显示。

结算按钮保持现有主流程：

- “返回乐园”
- 下一关或“全部关卡”
- 再次挑战

新增一个次级入口“查看本次藏品”，打开合并图鉴并定位当前关卡详情。它不替代现有主按钮。

## 7. 数据模型

### 7.1 称号目录

新增荣誉称号目录，建议放在 `src/data/honorTitles.ts`：

```ts
type HonorTitleCategory = "growth" | "chapter" | "mastery";

interface HonorTitle {
  id: string;
  name: string;
  description: string;
  category: HonorTitleCategory;
  achievementId: string;
  order: number;
}
```

称号不单独保存解锁时间。称号是否解锁由对应成就是否存在解锁记录决定，保持单一来源。

### 7.2 成就关联

`Achievement` 增加可选字段：

```ts
rewardTitleId?: string;
```

一个成就最多关联一个称号。称号目录必须能反查到唯一成就。

### 7.3 佩戴状态

`ParkProgress` 增加：

```ts
equippedTitleId: string | null;
```

默认值为 `null`。`sanitizeProgress` 只接受称号目录中存在的字符串 ID；不在目录中的值回退为 `null`。

实际显示时继续校验对应成就是否已解锁。存档中即使出现手工伪造的称号 ID，也不会显示未解锁称号。

### 7.4 新增成就条件

新增成就继续使用 `checkVictoryAchievements` 的同一统计对象：

- 累计完成数量读取 `clearedLevelIds.length`。
- 章节完成读取 `clearedLevelIds` 是否覆盖章节区间。
- 三星数量读取 `threeStarLevelIds.length`。
- 四星继续使用 `speed_optimizer` 的现有判定。

不新增第二套通关统计，不复制星级算法。

## 8. 组件边界

为控制 `CandyThemeShell.tsx` 继续膨胀，拆出两个组件：

| 组件 | 职责 |
|---|---|
| `RepairAtlasModal` | 章节页签、设施卡片、设施详情、章节进度和关卡选择回调 |
| `HonorProfile` | 当前称号、称号墙、成就分类、佩戴回调 |

`CandyThemeShell` 保留整体弹窗协调、首页入口、通关结算、音效和进度刷新。

数据职责：

- `content` 提供关卡与藏品关联。
- `rating` 提供最高星级。
- `achievements` 提供成就状态、进度和新解锁结果。
- `honorTitles` 提供称号目录和成就关联。
- `parkProgress` 保存佩戴选择。

## 9. 交互流程

### 9.1 选择关卡

1. 点击底部“关卡”。
2. 打开“乐园修复图鉴”并定位当前章节。
3. 点击设施卡片。
4. 查看藏品信息、星级和机制。
5. 点击“开始修复”或“再次挑战”。

### 9.2 局内查看图鉴

1. 关卡内点击图鉴图标。
2. 打开合并页并直接显示当前设施详情。
3. 返回本章图鉴或直接开始/重玩当前关卡。

### 9.3 解锁称号

1. 关卡完成后先写入通关、最佳成绩和首通奖励。
2. 成就检查读取最新统计并返回本次新解锁成就。
3. 有关联称号的新成就转换成称号结果。
4. 没有佩戴称号时，按称号目录 `order` 自动佩戴本次已解锁称号中最靠后的一个。
5. 结算页展示新称号。
6. 修复师档案立即显示新称号和对应成就进度。

### 9.4 佩戴称号

1. 打开头像进入修复师档案。
2. 切到“称号墙”。
3. 点击已解锁称号。
4. 当前称号立即更新并写入进度存档。
5. 首页和后续结算使用新称号。

## 10. 视觉约束

- 合并后的关卡卡片继续使用现有糖果立体材质。
- 未修复藏品与已修复藏品必须保持同一轮廓和中心点，避免切换时跳动。
- 4 列卡片在 360×800、390×844 和 430px 宽度下均需完整显示名称。
- 当前关卡描边不能盖住星级和地狱标记。
- 称号文字必须适配 2–6 个汉字，不能截断。
- 600px 以下不显示横向滚动。
- 章节全修复状态使用现有金色与章节主色，不引入新的 UI 材质体系。
- 首版不制作 12 张独立徽章插画，使用现有缎带、皇冠、星星和锁图标组合，后续再替换为专属徽章。

## 11. 测试与验收

### 11.1 数据测试

- 1–99 每个关卡都能同时取得关卡内容和藏品内容。
- 每个章节恰好显示对应区间的关卡，共 99 张设施卡。
- 12 个称号 ID 唯一，每个称号只关联一个成就。
- 每个关联成就都能在成就目录中找到。
- 已有 14 个成就的 ID 和解锁时间保持兼容。

### 11.2 图鉴测试

- 新玩家进入任意已解锁章节，未修复设施显示剪影。
- 完成关卡后，对应卡片变为彩色藏品并更新星级。
- 当前关卡同时显示金色当前描边和修复状态。
- 章节锁定、章节全修复和地狱关标记均正确。
- 点击卡片进入详情，详情主按钮能够开始或重玩对应关卡。
- 局内图鉴入口直接定位当前设施。
- 独立图鉴入口和独立图鉴弹窗不再出现。

### 11.3 称号与成就测试

- 首次完成第 1 关解锁“初亮星火”并自动佩戴。
- 完成第 10 关解锁“巡园修复师”。
- 累计完成 30、50 关分别解锁对应称号。
- 完成每个章节解锁对应章节称号。
- 一次四星、5 个三星和 20 个三星分别解锁对应技艺称号。
- 重复通关已经达成的条件不会重复显示新称号。
- 称号墙显示解锁条件和进度。
- 佩戴称号后刷新页面仍保持。
- 非法称号 ID 回退为空。
- 重置本地存档后称号、成就和佩戴状态全部清空。

### 11.4 结算与回归测试

- 首次通关同时显示图鉴收录、奖励和本次新称号。
- 同次解锁多个称号时集中显示，不弹多个窗口。
- 已通关重复挑战只更新最佳成绩，不重复首通奖励或称号。
- 旧存档读取后，已通关、星级、成就和货币不丢失。
- 主棋盘、提示、撤销、商店、无尽挑战和关卡工坊相关测试保持通过。

### 11.5 视觉验收

使用真实运行截图检查：

- 360×800 与 390×844 的图鉴首页和设施详情。
- 当前关卡、未修复、已修复、章节完成四种状态。
- 修复师档案的称号墙与成就页签。
- 首次称号解锁后的通关结算。

验收重点为文字完整、点击区域足够、藏品轮廓一致、星级可读、当前关卡可辨认、金色提示不过曝。

## 12. 首版不做

- 99 个逐关专属称号。
- 称号数值加成。
- 称号排行榜或社交展示。
- 赛季称号和限时称号。
- 称号徽章独立原画。
- 收藏品筛选、搜索和排序。
- 改动关卡盘面、难度、首通奖励或章节解锁规则。

## 13. 完成标准

- 玩家只通过“关卡”入口即可完成选关、看图鉴、读藏品和重玩关卡。
- 首页不再出现重复的独立图鉴入口。
- 每个关卡完成后，设施收录、星级和章节进度在同一界面更新。
- 成就页显示可理解的实时进度。
- 12 个称号可通过主线推进和修复技艺稳定解锁、佩戴和持久化。
- 旧存档无损读取，现有玩法和奖励口径不变。
