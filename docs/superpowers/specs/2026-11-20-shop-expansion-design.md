# 乐园商店首批扩充设计

日期：2026-11-20

## 目标

把当前只有“提示灯泡”的商店扩充为首批 8 件商品，形成两类明确用途：

- 补给帮助玩家继续解谜，失败后仍有主动补救手段。
- 装扮把 99 关的修复成果带回首页，形成长期购买与布置目标。

本批使用现有钻石结算，所有交易在本地即时生效并持久化。首批完成后，商店拥有 4 件可重复购买的补给和 4 件一次性装扮。试炼券、纪念册页和更多季节装扮留到第二批。

## 不做内容

- 不增加金币、体力、生命、复活或第二种购买货币。
- 不售卖关卡、章节钥匙、直接过关、直接加星或首通奖励加成。
- 不做随机商品、盲盒或限时倒计时。
- 不在本批实现特殊挑战关卡。

## 商品清单

### 补给

| 商品 | 价格 | 作用 | 使用条件 |
| --- | ---: | --- | --- |
| 提示灯泡 | 120 | 查看当前局面下一步正确操作 | 主线关卡进行中；已有提示计算失败时不扣库存 |
| 火花透镜 | 260 | 连续查看当前局面接下来的 3 步正确操作 | 主线关卡进行中且剩余步数足够；计算失败时不扣库存 |
| 时光回针 | 180 | 当前这一局回溯次数 +1 | 关卡进行中且尚未结算；离开或重置后本局加成失效 |
| 应急线圈 | 300 | 步数归零后补回 3 步 | 普通主线关卡步数已归零；零容差达标关不开放 |

补给可以重复购买并显示库存。提示灯泡保持新玩家初始 3 个；火花透镜、时光回针、应急线圈初始库存为 0。

应急线圈不会提高星级。补回的步数仍计入真实操作步数，因此有协助完成的关卡通常只能获得低星；零容差达标关隐藏该入口，保持“一次做对”的规则。

### 装扮

| 商品 | 价格 | 开放条件 | 作用 |
| --- | ---: | --- | --- |
| 开心问候 | 450 | 已修复 5 处设施 | 三位伙伴在首页显示开心表情气泡，可切换回默认状态 |
| 星愿礼服 | 900 | 已修复 20 处设施 | 三位伙伴在首页换装并保持现有站位、脚底基线和视觉比例 |
| 星空展台 | 1,200 | 已修复 10 处设施 | 在浮空岛右上空地陈列任意一件已修复设施，可更换或收起 |
| 宁静夜灯 | 1,800 | 已修复 40 处设施 | 使用现有深靛夜空与暖纸阅读界面的乐园主题，可恢复默认主题 |

装扮购买后永久拥有。重复点击只会切换使用状态，不会再次扣费。未达到开放条件时显示“修复 X 处后开放”；未拥有时不能装备。

开放条件统一按 `clearedLevels.length` 计算，章节锁定不额外影响商店开放。

## 商店界面

商店顶部固定显示当前钻石余额，下方提供“补给”和“装扮”两个页签。

- 补给页按单列显示 4 件商品，每件包含图标、名称、用途、价格、库存和购买按钮。
- 装扮页按单列显示 4 件商品，每件包含预览、名称、用途、开放条件、价格和“购买 / 使用 / 使用中 / 恢复默认”状态。
- 商品状态只使用“未开放、钻石不足、可购买、已拥有、使用中”五种。
- 星空展台购买后出现“选择展品”，打开已修复藏品列表；选择后立即回到首页展示。
- 宁静夜灯购买后出现“使用主题”；默认主题对应“恢复默认”。
- 当前货架不隐藏未开放商品，玩家始终能看到 8 件商品和后续目标。

商店主体拆为独立 `ShopModal` 组件，接收进度、通关数和操作回调。`CandyThemeShell` 只负责打开弹窗、保存返回的进度并协调局内动作，避免继续扩大现有大文件。

## 首页装扮

### 开心问候

使用素材包中三组现有表情头像，在羊、兔子、精灵上方分别显示轻量表情气泡。气泡不改变角色站位、点击区域和设施预览。

### 星愿礼服

为羊、兔子、精灵制作同一套星光庆典服饰，分别输出独立透明 WebP。替换首页角色图片时沿用当前三个角色的容器尺寸、底边和中心位置。

### 星空展台

在浮空岛右上方增加 18cqw 圆形星窗展台，避开标题、设置按钮和左侧功能区。展示图直接使用玩家选择的 `exhibit-*.webp`，下方显示藏品名。展台不遮挡伙伴和关卡卡片。

### 宁静夜灯

复用现有 `src/theme-calm.css`。装备后给根节点设置 `data-theme="calm"`，恢复默认时移除该属性。开发用 `?theme=calm` 仍可强制预览该主题。

## 数据模型

在 `ParkProgress` 中追加以下字段，旧存档缺少字段时自动补默认值：

```ts
interface ParkProgress {
  // 现有字段保持不变
  coins: number;
  hints: number;
  rewardedLevels: number[];
  completedDate: string;
  claimedDate: string;

  lenses: number;
  rewindTokens: number;
  stepTokens: number;
  ownedCosmetics: CosmeticId[];
  equippedCosmetics: {
    mood: "default" | "joy";
    outfit: "default" | "starlight";
    exhibitId: number | null;
    theme: "default" | "calm";
  };
}
```

`CosmeticId`、`SupplyId`、商品名称、价格、开放条件和分类统一放在 `src/data/shopCatalog.ts`。进度模块只调用目录中的价格和 ID，界面不复制价格常量。

新增进度读写规则：

- 计数字段使用现有 `asCount` 规则，非法值回落为默认值。
- `ownedCosmetics` 去重并过滤目录中不存在的 ID。
- 未拥有装扮的装备值回落为默认值。
- `exhibitId` 必须是 1–99 的整数；首页只在对应设施已修复时显示。
- 重置本地存档时同时清除补给库存和全部装扮。

## 交易与使用流程

### 购买

1. 商店从商品目录读取价格。
2. `buySupply(progress, id)` 检查余额，扣除钻石并增加 1 个库存。
3. `buyCosmetic(progress, id, clearedCount)` 检查余额、开放条件和是否已拥有，扣除一次钻石并加入拥有列表。
4. 任何条件不满足都返回原进度，不写半完成状态。
5. 成功结果通过现有 `save` 写入 `energy_park_progress_v2`，界面立即刷新库存、余额和按钮。

### 提示与火花透镜

- 现有单步提示继续调用 `findHint`。
- 新增 `findHintSequence`，从当前真实盘面连续计算最多 3 个正确操作。
- 提示弹窗按 1、2、3 列出操作；棋盘高亮第 1 个操作对应的格子。
- 计算不到第 1 步、剩余步数不足或关卡不支持计算时给出原因，不消耗库存。
- 火花透镜只用于主线关卡，避免对无尽和工坊给出不可靠路线。

### 时光回针

- 背包和操作历史中提供“使用回针”入口。
- 使用后库存减 1，并通过 `App.onAddRewind` 给本局 `rewinds + 1`。
- 已用完回溯时也能先补 1 次再撤销。
- 重置关卡后本局增加的次数消失，未使用库存保留。

### 应急线圈

- 现有免费补步改为消耗库存。
- 步数归零遮罩显示“应急线圈 × 库存”，库存不足时按钮禁用并显示“应急线圈不足”。
- 使用后库存减 1、补回 3 步，保留当前盘面与操作历史。
- `level.goal !== undefined` 时不显示入口。

## 素材生产

- 补给产品图标沿用提示、回溯、补步语义，新增火花透镜与应急线圈独立图标；图标保持现有 3D 糖果材质和透明边缘。
- 开心问候使用素材包中的 `xingya_*`、`boling_*`、`yunrong_*` 表情头像，整理为首页角色对应资源。
- 星愿礼服以三张现有主立绘为造型参考，生成同一服装语言的羊、兔子、精灵透明立绘，逐张检查主体完整性、裁切、尺寸、脚底基线和透明边缘。
- 星空展台直接使用现有 `exhibit-001.webp` 至 `exhibit-099.webp`，不生成重复藏品图。
- 宁静夜灯使用现有主题实现，商品预览由运行时界面缩略图或主题色样式组成。
- 所有新运行资源加入 `public/assets/park/manifest.json`，记录来源、尺寸、透明边界和处理方式。

## 测试与验收

### 数据测试

- 新玩家读取到 3 个提示和 3 类补给库存 0。
- 追加字段前生成的存档可无损读取并补默认值。
- 4 件补给均可正确扣费、增加库存、消耗库存，且库存不会低于 0。
- 钻石不足、商品未开放或计算失败时进度对象不变。
- 4 件装扮均只扣费一次；重复购买不扣费。
- 未拥有装扮不能装备；非法值与未知 ID 自动回落为默认。
- 展品 ID 过滤到 1–99，并在设施未修复时不显示。
- 商店目录 ID 唯一，价格与开放条件符合本规格。

### 玩法测试

- 提示灯泡和火花透镜分别显示 1 步、最多 3 步，并高亮第一个正确格子。
- 连续提示覆盖基础管、能量闸和联动轴关卡。
- 时光回针在回溯为 0 时可增加次数并完成撤销。
- 应急线圈只在步数归零的普通主线关可用，补步后继续操作。
- 零容差达标关不出现应急线圈。
- 补步不会凭空增加星级。

### 界面与持久化测试

- 从首页真实点击进入商店，切换两个页签并购买全部商品。
- 购买后余额、库存和按钮状态立即变化；刷新页面后保持。
- 购买并装备装扮后，首页出现对应表情、服饰、展品和主题。
- 恢复默认主题、收起展品、卸下装扮后首页恢复原样。
- 使用 360×800、390×844、430×932 三种手机视口截图检查：文字不截断、不溢出、不重叠，按钮可点击，商品卡可正常滚动。
- 检查默认主题和宁静夜灯下的对比度、棋盘可读性与角色边缘。

本功能属于新模块，需要新增商店与库存自动化测试，并在实施完成后运行现有全量测试、类型检查和构建。界面提交前必须完成真实运行截图和商业级手机视觉验收。
